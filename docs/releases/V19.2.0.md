# RedPA AI V19.2.0

## AWS Runtime Deployment

RedPA AI V19.2.0 extends the V19.1 AWS infrastructure foundation into a real running AWS workload.

### Added

- AWS ECS/Fargate runtime deployment for the RedPA backend.
- Two public subnets across `eu-central-1a` and `eu-central-1b`.
- Internet Gateway and public routing for runtime validation.
- Dedicated ECS task execution role.
- ECS service running the RedPA backend with `desired_count=1`.
- Redis 7 Alpine sidecar for runtime middleware dependencies.
- CloudWatch runtime logging.
- Pulumi-managed encrypted JWT runtime secret.
- Immutable ECR image deployment using the `v19.2.0` tag.

### Runtime Validation

Validated on AWS:

- ECS service status: `ACTIVE`.
- ECS rollout state: `COMPLETED`.
- Backend container: `RUNNING / HEALTHY`.
- Redis container: `RUNNING / HEALTHY`.
- Public liveness endpoint: PASS.
- `/docs`: HTTP 200.
- CloudWatch logs: PASS.
- Pulumi post-deployment preview: 16 resources unchanged.

### Scope Boundary

V19.2 validates the RedPA backend as a real AWS ECS/Fargate workload.

It does not claim a complete production deployment.

Current boundaries:

- runtime environment remains `development`;
- PostgreSQL is not yet connected to a managed AWS database;
- deep readiness is not claimed;
- direct public port `8000` access is validation-only;
- HTTPS/ALB production ingress is not yet implemented.

The next cloud evolution can focus on managed stateful services, private networking, HTTPS ingress, and production-grade readiness.
