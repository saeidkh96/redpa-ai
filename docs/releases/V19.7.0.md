# RedPA AI V19.7.0

## AWS Production Hardening & Recovery Readiness

RedPA AI V19.7.0 extends the AWS deployment validated in V19.3 with
controlled ingress, runtime resilience, infrastructure observability,
and recovery-readiness validation.

### Controlled ingress

- Added an AWS Application Load Balancer in front of the ECS/Fargate backend.
- Registered the backend through an IP target group with application health checks.
- Closed direct public access to backend port 8000.
- Restricted backend ingress to the ALB security group.

### ECS resilience

- Enabled deployment circuit breaker protection.
- Enabled automatic rollback for failed deployments.
- Enabled Availability Zone rebalancing.
- Configured a 60-second health-check grace period.
- Preserved rolling deployment capacity at 100/200 percent.

### RDS hardening

- Preserved private, encrypted PostgreSQL on Amazon RDS.
- Enabled deletion protection.
- Enabled snapshot tag propagation.
- Retained the one-day automated backup window required by the current AWS account tier.
- Validated active encrypted automated backups and encrypted automated snapshots.
- Validated an available point-in-time restore window.

### AWS observability

- Retained ECS Container Insights.
- Retained 30-day RedPA application log retention.
- Added CloudWatch alarms for:
  - ECS CPU utilization
  - ECS memory utilization
  - ALB unhealthy targets
  - ALB target HTTP 5xx responses
  - ALB target response time
  - RDS CPU utilization
  - RDS free storage space

### Recovery validation

A controlled ECS task failure was injected against the live development
deployment. ECS automatically provisioned a replacement task, the new task
became healthy, the ALB registered the replacement target, application
liveness recovered successfully, and the service returned to steady state.

### Current deployment boundary

The validated AWS environment remains a development validation environment.
RDS is intentionally single-AZ and automated backup retention is limited to
one day by the current AWS account tier. HTTPS/custom-domain ingress and
multi-AZ database deployment are not claimed by this release.
